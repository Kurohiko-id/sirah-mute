# Kuro Mute v2 — Core Tray Implementation Plan (plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust `kuromute.exe` tray process that fully replaces the C# app's runtime behavior (mute toggle, popup, border, device guard, autostart, update check, tray) with the settings edited as `config.json` — usable as a daily driver before the settings UI exists.

**Architecture:** One single-threaded Win32 message loop on a hidden top-level window owns all state. Core Audio COM callbacks and worker threads only `PostMessage` to that window. Pure logic (config, migration, hotkey rules, geometry, enforcer, i18n, update compare, wav) lives in side-effect-free modules with unit tests; Win32/COM wrappers are thin and verified manually in Task 14.

**Tech Stack:** Rust (edition 2024, toolchain 1.99), `windows` crate (latest on crates.io), `serde` + `serde_json`, `winresource` (build-dep, exe icon). Nothing else.

**Spec:** `docs/superpowers/specs/2026-11-09-rust-rewrite-design.md`

**Plans 2 and 3 (not here):** Plan 2 = settings window (`--settings`, Slint, layout B). Plan 3 = installer (Inno, new AppId), GitHub Actions, README/SmartScreen notes. Until Plan 2, `--settings` is a stub that opens `config.json` in Notepad and tells the core to reload when Notepad closes.

## Global Constraints

- Project lives in `kuromute/` at repo root (crate name `kuromute`, single binary). Old C# files are not touched.
- No admin rights, no telemetry, no network except the GitHub releases check.
- Config: `%APPDATA%\MuteMic\config.json`. Legacy `%APPDATA%\MuteMic\settings.json` is **read only, never written**.
- Logs: `%APPDATA%\MuteMic\logs\kuromute.log`, ISO 8601 timestamps with date, rotate at 1 MB, keep 3 old files.
- Hotkey registered with `MOD_NOREPEAT` (0x4000); bare F12 rejected; modifiers optional; F13–F24 and media keys allowed.
- Endpoint ID format: capture `{0.0.1.00000000}.{guid}`, render `{0.0.0.00000000}.{guid}`, guid lowercase.
- Default device is set for all three roles: eConsole, eMultimedia, eCommunications. Drift is checked on all three.
- Popup: base 220×100 logical px, margin 24 logical px from the work area, background #131417 at 95% opacity, text/icon #D7DADF, auto-hide 1500 ms, scale clamped to 0.5–2.0.
- Border: color #E5484D, thickness 1–30 **physical** px (same as the old app), 4 strips per monitor.
- Every overlay window: `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_LAYERED`; never takes focus.
- Process DPI awareness: Per-Monitor V2 (`SetProcessDpiAwarenessContext` first thing in `main`).
- UI strings: English + Indonesian; `language: Auto` follows `GetUserDefaultUILanguage` (primary lang 0x21 → Indonesian).
- Tray menu order: Settings…, Guard devices ✓, Check for Updates, Report Bug…, Exit.
- Notifications use tray balloons (`NIF_INFO`). Windows 10/11 render these as native toasts and respect Focus Assist, so no AUMID or Start Menu shortcut is needed. Plan 3 can upgrade to real toasts if action buttons are wanted.
- Commits: one topic each, **no AI attribution / Co-Authored-By lines**.

## Review Focus

1. **Chosen mic unplugged (at startup or mid-session) when the hotkey is pressed.** Expected: no crash. A balloon or tooltip says the mic is disconnected. Pressing the hotkey does not open settings when a mic *is* configured. Plugging the mic back in re-attaches and syncs the indicator. → Task 13 `hotkey_action` tests.
2. **Hand-edited or half-written `config.json`** (typo, truncated by power loss). Expected: the app still starts on defaults, the bad file is kept as `config.json.bad`, the user is told once, and nothing is overwritten silently. → Task 1 tests.
3. **Out-of-range or unknown values in config** (scale 5.0, thickness 0, position "Middle", unknown fields). Expected: values are clamped or defaulted, nothing panics, unknown fields are ignored. → Task 1 tests.
4. **Another app keeps switching the default device back.** Expected: after 5 reverts in 60 s the guard pauses for 5 minutes and notifies once, with no ping-pong. → Task 7 tests.
5. **A selected monitor is unplugged or renamed while muted.** Expected: indicators fall back to the primary monitor and stay visible. → Task 6 `monitors::select` tests.

    - sound off

### Task 7: Enforcer (device guard decision logic)

**Files:**
- Create: `kuromute/src/enforcer.rs`

**Interfaces:**
- Consumes: `Config`, `GuardMode`.
- Produces:
  - `#[derive(Default, Clone)] pub struct Defaults { pub capture: [Option<String>; 3], pub render: [Option<String>; 3], pub input_present: bool, pub output_present: bool }`. The arrays are indexed console, multimedia, communications. The `*_present` flags mean the *locked* device is active.
  - `#[derive(PartialEq, Debug)] pub enum Action { None, Revert { input: bool, output: bool }, Notify { input: bool, output: bool }, GiveUp }`
  - `pub struct Enforcer` (private history `VecDeque<Instant>`, `paused_until: Option<Instant>`)
  - `impl Enforcer { pub fn new() -> Self; pub fn evaluate(&mut self, cfg: &Config, cur: &Defaults, now: Instant) -> Action; pub fn reset(&mut self) }`
- Rules, in order:
  1. Return `None` if `!guard_enabled` or the mode is `Off`.
  2. Input drift = `default_input_id` is set, `input_present`, and any capture role differs. Output drift is the same with render.
  3. Return `None` if there is no drift.
  4. In `Notify` mode, return `Notify`.
  5. In `AutoRevert` mode, return `None` while `now < paused_until`. Otherwise drop history entries older than 60 s. If 5 entries remain, set `paused_until = now + 300 s`, clear the history and return `GiveUp`. If not, push `now` and return `Revert`.
- `reset()` clears both the history and the pause. It runs when the user flips the guard switch back on.

**Files:**

**Interfaces:**

- `main.rs` flow:
  1. `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`.
  2. `log::init(data_dir()/"logs")`, then `install_panic_hook()`.
  3. Dispatch the CLI arguments:
     - `--list-devices`
     - `--toggle`: find `KuroMuteCore` and post `KuroMute.Toggle`; if no core is running, print "not running" and exit 1.
     - `--settings`: Plan 1 stub. Open `config.json` with `notepad.exe`, wait for it to exit, post `KuroMute.Reload`.
     - No argument: run the core.
- Core startup, in order:
  1. Single instance: `CreateMutexW("Local\\KuroMute.Core")`. On `ERROR_ALREADY_EXISTS`, post `KuroMute.ShowSettings` to the existing window and exit 0.
  2. `CoInitializeEx(APARTMENTTHREADED)`.
  3. Load the config:
     - `Missing` + legacy file present → `from_legacy` → `save`, log "migrated".
     - `Missing` with no legacy file → defaults → `save`.
     - `Corrupt` → defaults (don't save until the user changes something) + balloon `ConfigCorrupt`.
  4. Register the class `KuroMuteCore` and create a hidden **top-level** window. Message-only windows don't receive `TaskbarCreated`.
  5. `Audio::new`, `Tray::add`.
  6. Validate and register the hotkey. On failure, show the `HotkeyFailed` balloon and put the same text in the tooltip.
  7. `monitors::enumerate` + `select` → `Indicators::rebuild`.
  8. `watch_mute(mic_id)` → set the tray state, and if muted, `show(true)`.
  9. If `force_on_startup`, call `set_default` on a worker for each configured id (only once per process start).
  10. `autostart::apply`.
  11. Spawn a worker that sleeps 10 s, calls `fetch_latest` and posts `WM_APP_UPDATE` only if `is_newer`.
  12. Enter `GetMessageW` loop.
- Window procedure: dispatch every message to a `thread_local! RefCell<State>`.

|---|---|
| `WM_HOTKEY` / `KuroMute.Toggle` | `hotkey_action` → open settings / balloon `MicDisconnected` / record `Instant::now()` in `pending_toggle_at`, then `toggle_mute()` |
| `WM_APP_MUTE` | `Indicators::show`, `Tray::set`, `sound::play` if `sound_enabled`, and if `pending_toggle_at` is set log `latency_ms=<n>` measured **after** `show` returns, then clear it |
| `WM_APP_DEVICES` | (re)arm a 300 ms timer `TIMER_DEVICES = 2` |
| `TIMER_DEVICES` | Re-run `watch_mute` (handles replug) → tray. Build `Defaults` → `Enforcer::evaluate`: `Revert` → worker `set_default` for the drifted side(s); `Notify` → balloon `DriftNotify` with `pending_balloon = ReapplyDefaults`; `GiveUp` → balloon `GuardPaused` |
| `WM_DISPLAYCHANGE`, `WM_SETTINGCHANGE`, `WM_DPICHANGED` | arm a 500 ms timer `TIMER_DISPLAY = 3` → enumerate + rebuild + re-show the current mute state |
| `WM_POWERBROADCAST` `PBT_APMRESUMEAUTOMATIC` | same as `TIMER_DISPLAY` plus `TIMER_DEVICES` |
| `TaskbarCreated` (registered) | `Tray::readd` |
| `WM_APP_TRAY` | left click (`NIN_SELECT`/`WM_LBUTTONUP`) → settings; `WM_CONTEXTMENU` → `menu`; `NIN_BALLOONUSERCLICK` → run `pending_balloon` (`ReapplyDefaults` / `OpenUrl(String)`) |
| `MenuCmd::ToggleGuard` | flip `guard_enabled`, `save`. When it turns on, call `Enforcer::reset` and run the `TIMER_DEVICES` logic immediately |
| `MenuCmd::CheckUpdate` | worker as above, but also post the `UpToDate` result |
| `MenuCmd::ReportBug` | open `https://github.com/Kurohiko-id/Kuro-Mute-Force-Mic-Input/issues/new?labels=bug&title=Bug%3A%20&body=...`, where the body has the app version (`CARGO_PKG_VERSION`) and OS build (registry `CurrentBuildNumber`) like `TrayApp.cs:80-91` |
| `KuroMute.Reload` | load the config (a corrupt result keeps the current config and shows a balloon) → `diff` → re-register the hotkey / `rebuild` + re-show / `watch_mute` / `Enforcer::reset` + evaluate / `autostart::apply`. **Never** re-run force-on-startup |
| `KuroMute.ShowSettings` / `MenuCmd::Settings` | spawn `current_exe --settings` unless the previous child is still running (`Child::try_wait`) |
| `MenuCmd::Exit` | unregister the hotkey, destroy indicators, remove the tray, `PostQuitMessage(0)` |
