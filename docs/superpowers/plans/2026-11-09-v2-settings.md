# Kuro Mute v2 Settings Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Notepad stub behind `kuromute.exe --settings` with a Slint settings window that edits every `Config` field, auto-saves, and reloads the core immediately.

**Architecture:** Settings runs as a separate process from the same exe. Core never initializes Slint. Settings writes `config.json` with `config::save`, then tells the core window to reload with `SendMessageTimeoutW`. Hotkey recording pauses the core hotkey and uses Raw Input inside the settings process only while recording. Pure logic (validation, config mapping, debounce, IPC outcome) lives in plain modules with unit tests. The Slint layer stays thin.

**Tech Stack:** Rust 2024 edition, `windows` 0.62.2 (already a dependency), Slint (added in Task 5, version pinned at add time), `slint-build` in `build.rs`.

**Spec:** [specs/2026-11-09-v2-settings-design.md](../specs/2026-11-09-v2-settings-design.md). Parent: [specs/2026-11-09-rust-rewrite-design.md](../specs/2026-11-09-rust-rewrite-design.md) §6.9, §6.10, §6.5.

## Global Constraints

- Core (`App::run`, the default path) must not initialize Slint. Slint code lives only under `kuromute/src/settings/` and `kuromute/ui/`, and runs only from the `--settings` branch of `main.rs`.
- No `WH_KEYBOARD_LL` anywhere, including the settings process. Recording uses Raw Input only.
- Never write the legacy `settings.json`. Only `config.json` is written, through `config::save`.
- Core RAM < 10 MB and hotkey-to-indicator p95 < 16 ms (measured with `kuromute/tools/measure.ps1`, Task 11).
- Strings go through `i18n::Key` (EN and ID), same table as the core.
- Settings must never make the core hang: every message from settings to core uses `SendMessageTimeoutW` with a 2000 ms timeout, never a blocking send.
- Commits: one per task (or per logical step inside a task), no AI attribution lines.

## Review Focus

1. **Config unreadable or corrupt at settings start.** Settings must not overwrite a file it could not read. Test: `save_and_reload` returns `SaveOutcome::Blocked` when the startup load was not ok (Task 4).
2. **Settings crashes or is killed while recording.** The core must re-register the hotkey without any user action. Test: core resumes hotkey when the child process has exited (Task 2).
3. **Monitor saved in `monitor_ids` is unplugged.** It must stay in the saved list and the list must still save. Test: `retain_known` keeps unknown IDs (Task 4).
4. **Core is not running when a setting changes.** The save must succeed and the UI shows the "not running" info line. Test: `map_reply(None, false)` gives `NotRunning` (Task 4).
5. **Hotkey already used by another app.** The config is saved, the UI shows the red error, and the core keeps its tray tip. Test: reply code `1` maps to `CoreReply::HotkeyFailed` (Task 4).

**Interfaces:**
- Consumes: `config::{Config, Hotkey, LoadOutcome, save}`, `hotkey::{validate, leaks_into_games, HotkeyError}`.
- Produces:
  - `model.rs`:
    - `pub fn retain_known(saved: &[String]) -> Vec<String>`: removes duplicates only, keeps unknown IDs (unplugged monitors stay).
    - `pub fn hotkey_choice(mods: u32, vk: u32) -> Result<Hotkey, HotkeyError>`: runs `hotkey::validate`.
    - `pub fn hotkey_warning(h: &Hotkey) -> bool`: returns `hotkey::leaks_into_games(h)`.
    - `pub struct Debouncer` with `pub fn new(ms: u64) -> Self`, `pub fn bump(&mut self, now_ms: u64)`, `pub fn ready(&self, now_ms: u64) -> bool`. Ready when at least `ms` has passed since the last bump.
  - `save.rs`:
    - `pub enum SaveOutcome { Saved(CoreReply), Blocked, WriteFailed(String) }`
    - `pub enum CoreReply { Ok, HotkeyFailed, Unknown, NotRunning }`
    - `pub fn map_reply(code: Option<isize>, timed_out: bool) -> CoreReply`: `Some(0)` → `Ok`, `Some(1)` → `HotkeyFailed`, timed out or any other value → `Unknown`, `None` with no timeout → `NotRunning`.
    - `pub fn save_and_reload(startup_load_ok: bool, path: &Path, cfg: &Config, send: impl FnOnce() -> Option<(isize, bool)>) -> SaveOutcome`. `send` returns `Some((code, timed_out))` when the core window was found, `None` when it was not found. If `startup_load_ok` is false, return `Blocked` without writing. Otherwise call `config::save`. On error return `WriteFailed`. On success call `send` and return `Saved(map_reply(...))`, or `Saved(NotRunning)` when `send` returns `None`.
