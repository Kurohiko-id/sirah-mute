# Sirah Mute v2.1 — desain

Induk: [2026-11-09-rust-rewrite-design.md](2026-11-09-rust-rewrite-design.md) dan
[2026-11-09-v2-settings-design.md](2026-11-09-v2-settings-design.md). Kalau bentrok, dokumen ini yang menang
untuk empat fitur di bawah.

## 1. Intent

Kurohiko streamer dengan batuk menahun. Mute sering, lupa unmute juga sering. Dari log stream 11 Nov:
18 kali toggle F13 dalam 2,5 jam, 4 kali ngomong pas mic masih mute. Ada juga mic kedua (PD400X) yang
kadang ke-mute oleh hal lain dan nggak ketahuan; sejauh ini dipantau tool pribadi terpisah
(`O:\Project 2026\Mute Mic\pd400x-watch`).

v2.1 nambah empat hal, urut prioritas:

1. **Pill bisa diklik buat unmute.** Lihat pill merah, klik, beres. Nggak perlu cari tombol.
2. **Tombol batuk.** F13 yang sama: tekan sebentar = toggle biasa; tahan = mute selama ditahan, unmute pas
   dilepas. Pas batuk tinggal tahan, nggak mungkin lupa unmute.
3. **Pantau mic lain.** Daftar mic tambahan; tiap yang ke-mute muncul pill "PD400X mute", klik = unmute.
   Gantiin PD400X Watch.
4. **Perintah buat HASS Agent.** `--mute` / `--unmute` / `--status`, supaya Home Assistant bisa kontrol dan
   baca status mic.

Rilis: v2.1.0, bareng statistik anonim yang udah di-commit (3d5906e..20d989e). Catatan rilis wajib
nyebut terang-terangan bahwa statistik anonim sekarang dikirim.

## 2. Goals / non-goals / anti-goals

**Goals**
- Empat fitur di atas, bisa diatur dari settings (kecuali CLI, nggak perlu setting).
- Semua jalan tanpa ganggu game: nggak ada jendela yang nyuri fokus.

**Non-goals**
- Integrasi OBS WebSocket (tetap di TODO, bukan v2.1).
- MQTT discovery untuk Home Assistant (nanti, kalau delay sensor HASS Agent kerasa).
- Plugin Stream Deck, pengingat mute kelamaan (dibatalkan user).
- Log forensik "siapa yang nge-mute" dari PD400X Watch (hook keyboard/mouse, nama proses). Nggak dipindah.
- Timer, suara, border, atau peringatan ngomong untuk mic lain. Mic lain cuma dapat pill.

**Anti-goals**
- Core makin berat atau hotkey makin lambat. Target tetap: RAM core < 10 MB, hotkey→indikator p95 < 16 ms.
  Ukur ulang setelah selesai (cara ukur sama dengan v2.0: `latency_ms` di log).
- Klik nyasar ke game. Yang boleh nangkep klik cuma pill yang lagi kelihatan; border dan area kosong
  jendela popup tetap tembus klik.
- Tombol batuk ngubah perilaku user lama tanpa diminta. Default mati.

## 3. Fitur A — pill bisa diklik

Berlaku hanya kalau `popup_style == Pill`. Kartu (Card) tetap tembus klik (keputusan Claude: kartu besar
di tengah layar lebih gampang kena klik nyasar).

- **Pill bisa diklik selama kelihatan** (keputusan user: "A"). Perilaku `popup_persist_while_muted` nggak
  berubah: kalau mati, pill hilang setelah ~1,5 dtk seperti biasa. Di settings (tab Penanda), saat gaya Pill
  dipilih, tampil catatan: "Nyalain *Tetap tampil selama mute* biar pill bisa diklik kapan aja." /
  "Turn on *Keep showing while muted* so the pill stays clickable."
- Jendela popup gaya Pill dibuat **tanpa** `WS_EX_TRANSPARENT`, dan `WM_NCHITTEST` nggak lagi balikin
  `HTTRANSPARENT` untuk jendela itu. Jendela layered per-pixel alpha (`UpdateLayeredWindow` + `ULW_ALPHA`)
  otomatis meneruskan klik di piksel alpha 0, jadi cuma bentuk pill yang nangkep klik.
  Pola ini udah kebukti di PD400X Watch (`pd400x-watch/src/main.rs`, wndproc sekitar baris 489-496).
- `WM_MOUSEACTIVATE` tetap `MA_NOACTIVATE`; `WS_EX_NOACTIVATE` tetap. Fokus game nggak pindah.
- Kursor jadi tangan (`IDC_HAND`) di atas pill (`WM_SETCURSOR`).
- `WM_LBUTTONUP` di pill → post ke jendela core (pesan baru, mis. `WM_APP_PILL_CLICK`) → core panggil
  **unmute** (bukan toggle) di mic utama.
- Selama pill nampilin "Mic on" (sudah unmute, ~1,5 dtk), `WM_NCHITTEST` balikin `HTTRANSPARENT` supaya klik
  tembus ke game (keputusan Claude, pakai flag state di popup).
- Border strip nggak berubah: tetap `WS_EX_TRANSPARENT` + `HTTRANSPARENT`.
- `Audio` butuh `set_mute(bool)` di samping `toggle_mute()`.

## 4. Fitur B — tombol batuk

**Config baru**
- `cough_hold: bool`, default `false`.
- `cough_hold_ms: u32`, default `400`, di-clamp `200..=2000` di `sanitized()`.

**Perilaku** (hanya kalau `cough_hold` nyala, dan hanya untuk hotkey; `--toggle`, klik pill, dan CLI nggak
kena):

| Saat tombol ditekan | Saat dilepas |
|---|---|
| Mic live → **mute langsung** | ditahan < `cough_hold_ms` → tetap mute (toggle biasa) |
| | ditahan ≥ `cough_hold_ms` → **unmute** |
| Mic mute → **unmute** (toggle biasa) | nggak ada apa-apa |

Indikator, suara, statistik ikut jalan seperti mute/unmute biasa (batuk panjang = satu mute + satu unmute).

**Cara deteksi lepas.** `RegisterHotKey` cuma ngasih key-down. Setelah `WM_HOTKEY` yang bikin mute, core
pasang timer 20 ms yang cek `GetAsyncKeyState(vk) & 0x8000`. Begitu bit itu 0, hitung lama tahan, putuskan,
matikan timer. Timer cuma jalan selama tombol ditahan, jadi nggak nambah beban di luar itu.

**Risiko yang harus dicek duluan (spike, langkah pertama implementasi):** apakah `GetAsyncKeyState` tetap
lihat F13 sedang ditekan padahal F13 ditelan `RegisterHotKey`. Uji dengan F13 dari tombol mouse user
(NOIR S1/macro) dan dari keyboard biasa. Kalau ternyata nggak kelihatan, ganti ke `WH_KEYBOARD_LL` hook
yang dipasang cuma selama tombol ditahan (lepas = `WM_KEYUP` dengan vk yang sama). Kalau macro mouse
ngirim down+up instan, lepasnya langsung terbaca → selalu jadi toggle biasa. Itu perilaku yang wajar.

**Hotkey dengan modifier** (mis. Ctrl+F13): "lepas" = tombol utama (`vk`) lepas; modifier diabaikan
(keputusan Claude).

**Latency.** `latency_ms` cuma diukur di jalur tekan. Unmute karena lepas tombol nggak dicatat sebagai
latency (keputusan Claude), biar p95 tetap sebanding dengan v2.0.

**Pengaman.** Kalau hotkey ditekan lagi selagi timer masih jalan (seharusnya mustahil karena
`MOD_NOREPEAT`), anggap sebagai lepas dulu. Timer dimatikan saat reload settings dan saat exit.

**Logika murni yang dites:** satu fungsi keputusan, mis.
`cough_release(held: Duration, threshold_ms: u32) -> bool` (true = unmute), plus tes untuk batas tepat
di threshold (≥ = unmute).

**Settings:** di tab Mic, bagian Hotkey: checkbox "Tahan untuk batuk" / "Hold to cough", di bawahnya
pengatur batas waktu (slider atau spinbox, langkah 50 ms, tampil "0,4 dtk" / "0.4 s"), nonaktif kalau
checkbox mati. Catatan kecil: "Tahan tombol = mute selama ditahan. Tekan sebentar = mute/unmute biasa."

## 5. Fitur C — pantau mic lain

**Config baru**
```rust
pub struct OtherMic { pub id: String, pub name: String, pub enabled: bool }
pub other_mics: Vec<OtherMic>,          // default kosong
pub other_mics_position: Position,      // default BottomLeft (sama dengan PD400X Watch)
```
- `name` dipotong ke 16 karakter di `sanitized()`. Kosong → pakai nama device (juga dipotong).
- Entri yang `id`-nya sama dengan `mic_id` diabaikan core (mic utama udah punya indikator sendiri).
- Entri dobel (id sama) → yang pertama yang dipakai.

**Audio.** `Audio` simpan daftar `(id, IAudioEndpointVolume, callback)` untuk mic lain yang aktif dan
`enabled`. Callback post `WM_APP_OTHERS` tanpa payload; core baca ulang `GetMute()` semua mic lain dan
gambar ulang kalau hasilnya beda dari sebelumnya (perubahan volume juga memicu callback, jadi wajib dibandingkan).
Daftar dipasang ulang di jalur yang sama dengan `rewatch()` (start, `TIMER_DEVICES`, reload settings).
Mic yang dicabut/nonaktif = nggak dipantau = nggak ada pill.

**Tampilan.**
- Satu jendela layered per monitor yang terpilih (pakai pilihan monitor yang sama dengan indikator utama:
  `all_monitors` / `monitor_ids`). Isinya deretan pill ke samping, jarak antar pill = jarak pill biasa.
- Teks pill: `"{name} mute"` + ikon mic dicoret (`GLYPH_MIC_OFF`), tanpa timer. Warna dan bentuk sama
  dengan pill utama. Skala ikut `popup_scale`.
- Urutan pill = urutan di daftar settings. Rata kiri untuk posisi *Left, tengah untuk *Center, kanan untuk *Right.
- Kelihatan selama minimal satu mic lain mute. Nggak hilang sendiri. Nggak ada suara, border, atau pulse.
- Tetap muncul walau `popup_enabled` mati (fitur ini terpisah; nyala kalau ada entri `enabled`).
- Kalau `other_mics_position == popup_position`, grup digeser satu tinggi pill + jarak menjauhi tepi layar
  (ke atas untuk Bottom*, ke bawah untuk Top*), selalu, biar nggak loncat-loncat (keputusan Claude).
- Tiap pill bisa diklik (pola sama dengan Fitur A): `WM_LBUTTONUP` → cari pill dari posisi x → core
  `set_mute(false)` di mic itu.
- Gambar ulang saat berubah saja (bukan jalur hotkey, nggak perlu pre-render).

**Logika murni yang dites:** layout grup, mis.
`pill_row(widths: &[f32], gap, area: Rect, pos: Position, main_pos: Position, pill_h) -> Vec<Rect>`
(posisi tiap pill di layar) dan `hit(rects, x) -> Option<usize>`.

**Settings: tab baru "Mic lain" / "Other mics"**, di antara Mic dan Penanda (urutan jadi Mic 0,
Mic lain 1, Penanda 2, Device 3, Umum 4; sesuaikan `tab` dan `tab-opened`).
- Daftar baris: dropdown device (mic input; mic utama nggak muncul di pilihan), kolom teks nama pendek,
  checkbox nyala/mati, tombol hapus.
- Tombol "+ Tambah mic": nambah baris dengan device input pertama yang belum dipakai (bukan mic utama).
  Kalau semua udah dipakai, tombol nonaktif. Maksimal 6 baris (keputusan Claude: lebih dari itu pill-nya
  kepanjangan).
- Dropdown "Posisi pill" (6 posisi, sama dengan posisi popup).
- Catatan: "Pill muncul selama mic ini mute. Klik pill buat unmute."
- Mic yang lagi dicabut tetap tampil di daftar dengan label "(nggak terpasang)", sama seperti dropdown mic utama.
- Auto-save + reload core seperti tab lain. Ketik nama: simpan saat selesai edit (`edited`/`accepted`), bukan tiap huruf.

**Ganti PD400X Watch.** Setelah v2.1 terpasang, user matiin PD400X Watch (hapus dari startup). Nggak ada
migrasi data.

## 6. Fitur D — perintah HASS Agent

```
sirahmute.exe --mute      sirahmute.exe --unmute      sirahmute.exe --status
```

- Ketiganya kirim satu pesan terdaftar baru (mis. `SirahMute.Remote`, wparam 0 = status, 1 = mute,
  2 = unmute) ke core lewat `SendMessageTimeoutW` (timeout 2000 ms). Core balas kode status setelah aksi:
  0 live, 1 mute, 2 no_mic (mic belum dipilih atau lagi dicabut). Mute/unmute pakai `set_mute`, bukan toggle.
- Keluaran (stdout, satu kata, tanpa newline tambahan selain satu `\n`) dan exit code:

| Keadaan | stdout | exit code |
|---|---|---|
| live | `live` | 0 |
| mute | `muted` | 1 |
| mic belum ada / dicabut | `no_mic` | 2 |
| core nggak jalan / nggak balas | `not_running` | 3 |

  State juga dikodein di exit code supaya tetap kepake kalau stdout nggak ketangkep.
- Exe ini GUI subsystem. Tulis ke stdout handle yang diwarisi dulu (pipe dari PowerShell/HASS Agent);
  `AttachConsole(ATTACH_PARENT_PROCESS)` cuma kalau handle itu nggak valid. Nggak boleh muncul jendela console.
- **Cek dulu di langkah implementasi:** `& "$env:LOCALAPPDATA\Programs\SirahMute\sirahmute.exe" --status | Out-String`
  di PowerShell 5.1 ngembaliin teksnya. Kalau nggak, README pakai exit code.
- Jalur remote nggak pernah buka settings atau munculin balon (beda dengan hotkey); mic belum dipilih atau
  dicabut cukup balas `no_mic` (keputusan Claude).
- Balasan beneran lewat `LRESULT`: pesan ini masuk `is_ours`, dan wndproc ngembaliin kodenya. Core nyimpen
  status terakhir di satu nilai cache (diperbarui di `on_mute`/`rewatch`), jadi `--status` tetap dijawab
  walau `State` lagi dipinjam (menu tray, reload). Mute/unmute yang datang saat `State` dipinjam ikut antre
  `DEFERRED` dan dibalas dengan status yang diminta (keputusan Claude).
- `--toggle` yang lama nggak diubah.

**README (EN + ID):** bagian "Home Assistant (HASS Agent)":
- 2 command (Custom/PowerShell) buat mute dan unmute.
- 1 sensor PowerShell buat status: `& "$env:LOCALAPPDATA\Programs\SirahMute\sirahmute.exe" --status | Out-String`.
- Catatan: versi portable pakai path folder zip-nya; status di HA telat sesuai interval sensor HASS Agent.
- Catatan buat user sendiri (bukan README): command HASS Agent yang sekarang di
  `commands.json` masih ngarah ke MicrophoneFX `4a0acd44` lewat cara lain; ganti ke perintah baru ini.

## 7. Bagian kecil yang ikut berubah

- `stats::features`: tambah `cough_hold` dan `other_mics` (cuma flag nyala, tanpa jumlah atau nama mic).
  Bagian Privacy README nggak perlu diubah selain daftar contoh fitur kalau ada.
- `app::diff` / `Changes`: flag baru untuk `other_mics*` (pasang ulang pantauan + bangun ulang grup pill) dan
  `cough_hold*` (cukup ganti nilai).
- i18n: semua teks baru EN + ID.
- `Cargo.toml` version → `2.1.0`. README fitur: tambah empat fitur.

## 8. Tes

**Otomatis:** `cough_release` (di bawah, pas, di atas batas), clamp `cough_hold_ms`, config lama tanpa field
baru → default, `sanitized()` motong nama, layout `pill_row` (6 posisi, tabrakan dengan popup utama),
`hit`, mapping kode balasan → kata/exit code, flag `diff` baru, `features` nggak bawa nama/id mic.

**Manual (user):**
1. Pill: mute → klik pill → unmute; fokus game nggak pindah; klik di samping pill tembus ke bawahnya;
   border tetap tembus.
2. Batuk: tekan sebentar F13 → mute; tekan lagi → unmute; tahan 1 dtk → mute, lepas → unmute.
   Dari tombol mouse dan dari keyboard. Ukur `latency_ms` tetap < 16 ms p95.
3. Mic lain: tambah PD400X, mute dari Wave Link → pill muncul; klik → unmute; dua mic mute → dua pill
   berjejer; cabut mic → pill hilang; posisi sama dengan popup utama → nggak numpuk.
4. HASS Agent: `--status` di PowerShell, lalu command + sensor di HASS Agent beneran.
5. Ukur RAM core setelah semua nyala.

## 9. Diserahkan ke builder

- Nama pesan/konstanta/fungsi persis, pembagian file (mis. `others.rs` atau masuk `overlay.rs`).
- Bentuk widget threshold (slider vs spinbox).
- Detail urutan pemasangan callback mic lain selama sesuai §5.
- Urutan task, asal spike `GetAsyncKeyState` dan cek stdout PowerShell dikerjakan duluan sebelum kode yang
  bergantung ke hasilnya.
